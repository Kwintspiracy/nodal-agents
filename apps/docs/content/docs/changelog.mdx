Notable releases, newest first. Pre-1.0: minor versions can carry breaking
changes. Every release is published to npm as `nodal-agents` and tagged on
GitHub — upgrade in place with `nodal-agents update` (your data is preserved).

## v0.9.0 — Sep 20, 2026

The product changed shape. The sidebar became a rail of five boards, a project
opens on its conversations with its folder beside it, and what Nodal opens on is
an empty conversation rather than a dashboard of numbers. Underneath, a run's
delivered files are read from git instead of from what the agent said it wrote.

**The sidebar, and what it opens**

- **Five boards in a rail: Work, Agents, Run, Approvals, Settings.** Each opens
  its own 300 px panel; Logs navigates and Help opens the documentation, the
  Discord and the public quality board. Which board is active is derived from the
  address alone, so two tabs on the same URL show the same panel and a link you
  send opens what it promises.
- **The default screen is a new conversation.** Opening Nodal puts you in front
  of an empty thread, not a dashboard. No row is written before your first
  message, so a thread opened and closed without a word no longer sits in your
  inbox forever. The dashboard of figures still exists, at `/dashboard`.
- **Settings is one list of four pages** — Access, Safety, Workspace, Install —
  each opening in place with the setting you picked. LLM Providers keeps its own
  page. Eleven stacked blocks became rows you can filter by name.
- **Back links are gone everywhere.** The sidebar already says where you are.
- **An inspector docked to the right edge**, which pushes the page instead of
  covering it: the list on its left stays visible and stays clickable, so you
  walk from one row to the next without closing anything.

**Work is a folder you open**

- **One projects page.** Workspaces lists both the projects you registered and
  the folders an agent wrote in that nobody declared — register one, or hide it.
  The old Code screen redirects here.
- **A project opens on its activity, with its folder beside it.** One sorted list
  of every conversation and every session, including runs started from the CLI or
  from an MCP client. "Files & proof" is a panel docked to the right, open by
  default, not a second screen.
- **An automation has its own page**: its settings, its last ten runs with what
  they cost over thirty days, and what the routine has remembered. One page
  serves a schedule and a webhook alike.
- **Nodal can run `git init` in a project folder** — an option, off by default,
  offered when you create a project and in its settings. It exists because the
  git reading below is the only one that sees what a command wrote without naming
  it, and someone who starts a project from Telegram has no repository to read.

**What a run really wrote**

- **Writes are read from git.** When the project folder is a repository, the
  runner reads `git status --porcelain` before and after each command, and the
  delta is the file list. A `run_command` that writes ten files without naming
  one used to leave no trace at all. Each file carries git's own word for what
  happened to it, "deleted" included. A folder that is not a repository falls
  back to the named-files rule, and the Files block says so rather than
  pretending.
- **A run records how its answer was produced**, so the run page and the thread
  no longer each guess, differently, whether the text is the agent's own words or
  a compiled relay.
- **A reviewer's own commands are kept** as proof of the work they reviewed, and
  the verdict sits next to what was delivered.
- **A refused command names the real cause.** A checkpoint that cannot finish
  still refuses the write; what changed is what it tells you — a typed code plus
  the facts measured right then, the folder's size, its file count and the limit,
  instead of one sentence for every cause.

**Threads**

- **Unread, per person and per thread.** The dot in front of a thread used to
  mean only "waiting for you, or running". A read now belongs to whoever read:
  the thread you just opened is not read by a teammate.
- **The chat reply appears as it is written**, word by word, instead of arriving
  whole at the end of the turn.

**Two guards against paying twice**

- **A second review of the same thing is refused, not run** — same reviewer, same
  target, nothing completed in between. An orchestrator that has a PR reviewed,
  has the findings fixed and asks again is asking about something that changed,
  and goes through.
- **An agent does not recompose its own team.** A per-agent setting,
  `may_change_team`, off by default and off for every agent that already exists:
  with it off the three team meta-tools are not in the list the runner computes,
  so the model never sees them.
- **Delegating expires the parent's prompt cache, and the run now says what that
  costs.** A sequential delegation always outlasts a provider's cache, so the
  parent re-pays its prefix at full rate on every resume — about a fifth of a
  run's bill. Nothing billed changes; the cost is read from the calls themselves
  and shown.

**Installing**

- **The install names npm's script gate before it bites.** npm skips the install
  scripts of `@embedded-postgres/<platform>`, the package carrying the Postgres
  binaries. The install page, the CLI reference, the self-hosting guide and this
  documentation now say what the warning means and give the command; `up` says it
  after the fact.

## v0.8.11 — Sep 19, 2026

A release about reading a run without opening a chat.

**A run is a board to follow, not a thread to read**

- **One page for every run**, whether it came from a schedule, from a project or
  from an MCP client: a header card with the request, the agent, the origin, the
  model and seven figures (cost, duration, tokens in and out, cache reads, files
  changed, last activity), then what was delivered, the review, the proof, the
  files of a code run, and the whole activity.
- **The run says which run it is** — the full identifier under the header,
  selectable, with a copy button.
- **A cost or a duration that is genuinely zero prints `0`.** A dash means
  absent. The two had been indistinguishable.
- **Audit rows are masked at the gate**: the card, the raw output and the input
  of every tool row go through one redaction before any screen sees them.

**The thread reads the verdict the reviewer recorded**

- **A delegation's head says the recorded verdict** — "Approved", or "Changes
  requested · 2 blockers, 1 minor" — read from the row the review tool wrote
  rather than from the first line of the child's prose, which could say the
  opposite.

**Channels, and what a failure asks of you**

- **An MCP folder in Channels.** Runs started from outside Nodal, through the MCP
  server or the API, get their own folder with multi-select delete that refuses
  to orphan a live delegation.
- **A failed run says the gesture it calls for.** When a provider rejects a
  request for a model, the failure says "Try another model for this agent"
  instead of leaving you with a provider code.
- **A restart never leaves a job processing with nobody on it.** Jobs whose
  runner stopped answering are reclaimed and marked, and a parent is woken only
  if the child it waited for is the one that died.
- **A late timeout keeps the turns already done** instead of discarding the job.

## v0.8.10 — Sep 16, 2026

A release about trusting what Nodal tells you.

**The launcher stops what is yours, and nothing else**

- **No recorded pid is killed unproven.** Windows recycles process numbers, so a
  process that took the place of a dead worker could be killed in its stead. A
  pid is signalled only when a fresh reading of the process table agrees on its
  name and its creation time. When the table cannot be read, nothing is signalled
  and the line says so.
- **`up` refuses to kill a healthy stack it did not start.** A live install on
  the configured ports used to be treated as leftovers to clean up.
- **Postgres keeps a log**, in `~/.nodalai/logs/postgres/`, one directory per
  data directory, rotated daily. A backend crash can now be read instead of
  guessed at.
- **`down` never sits silently.** Past its budget it reports what the postmaster
  is still doing and the exact command to end it, for a pid it confirmed.

**An agent's work is credited when the disk says so**

- **A write is recognised by its content**, not by a size and a timestamp whose
  resolution depends on the filesystem. A rewrite of the same size in the same
  second is now seen.
- **A refused read is not an absent file.** A file the runner cannot open after
  the tool ran is neither credited nor invented.
- **A project is a project everywhere.** Six places decided whether a folder was
  a code project and did not agree. A folder you hid stays hidden in the agent's
  context too, not just on screen.

**Fixes**

- **`release:check` refuses to run over a live dev stack** instead of building in
  place and emptying the folder the running dashboard is served from.
- **A delegated job that produced nothing is a failure**, not a completed job.
  The parent no longer tells you work is "launched" when the specialist returned
  no deliverable.

## v0.8.9 — Sep 9, 2026

Nodal now proves what it builds. Until this release its verification engine had
never run once — not in your install, not in any install.

**Your agents prove their own work**

- **Verification had never run. Not once.** The engine existed, the screen
  existed, and the table that records proof had been empty since day one. The
  reason was a question nobody wanted to answer: Nodal asked _you_ which commands
  prove your project. **The agent that built the thing now declares how to check
  it**, and Nodal runs that check when the work ends. A project turns green or
  red with the command that decided it, and the output that explains it.
- **What an agent already ran is what it declares** — the syntax check, the
  build, the request against a server it started. These are not new powers; they
  were simply never recorded. Declaring them is subject to the same approval
  rules as running them.
- **A deliverable is what was aimed at.** A finished app used to be listed with
  twenty unverified deliverables, archive folders included, because a shell
  declares everything it _could_ write.

**Every agent gets a purpose, at creation**

- **Creating an agent starts from what you want it for**, not from an empty form.
  Profiles pre-fill the model, the tools and the autonomy that fit, and
  everything stays editable, because nothing exists in the database until you
  click.
- **Connectors are recommended, never imposed.**

**The chat thread tells the truth**

- **A chat row opens the thread your next message will land in.** It could open
  another one: the screen picked the most recently _touched_ thread while the
  runner picks the most recently _opened_ one.
- **Channels and dashboard conversations are two lists**, one row per chat, named
  after the person or room at the other end rather than after the first message
  ever sent.
- **Threads scroll like a messenger** — open at the last message, follow new
  ones, but only if you were already at the bottom.

**Scheduled runs remember what they did**

- **A routine keeps its own state**, read and written without a model. It used to
  store "what I last announced" as a memory searched back in plain language, and
  a memory that got cleaned up made it announce a release twice on a public
  Discord.
- **Memories stop filling with logbook entries.** More than a third of an agent's
  memory was routine reports. Memory is what an agent knows about you.

**Faster, cheaper conversations**

- **A chat turn costs about half of what it did.** Every turn silently made a
  second full-size call to re-ask a question whose answer depended on none of the
  context it was sending — roughly nine thousand tokens, on every message,
  including "hello".

**Fixes**

- **Signing in over the local network works again.** The dashboard had answered
  500 in LAN mode since v0.8.7.
- **A project can no longer contain another project**, and naming a project's
  folder is optional — leave it empty and it takes the project's name.

## v0.8.8 — Aug 28, 2026

Your bot tokens stop being readable in the database, a Slack bot that loses its
connection comes back on its own, and a database outage no longer destroys the
log that would explain it.

**Every credential is now encrypted at rest**

- **Bot tokens leave the clear.** The Discord, Slack, WhatsApp and Telegram
  credentials — and the secret that authenticates your inbound webhooks — were
  the last values stored readable in the database. They are now encrypted with
  the same key as your API keys and OAuth credentials. Existing installs are
  migrated on the next start, in place, with nothing to do.
- **Reading the database is no longer enough to use them.** A webhook secret is
  compared after decryption, so a copy of your database does not let anyone fire
  your agents.
- **A credential that cannot be decrypted says so.** Restoring a backup without
  its key used to look exactly like "no bot configured here".

**A Slack bot that drops comes back**

- **A revoked or rotated token no longer leaves an agent silently offline.** The
  connection is re-established on its own with the credentials as they stand at
  that moment, so rotating a token is enough to recover.
- **Retries slow down instead of hammering.**

**A database outage no longer erases its own explanation**

- **Repeated failures collapse.** With the database unreachable, seventeen places
  wrote the same line every 30 seconds — one real log had 7 412 such lines out of
  61 359, and since logs rotate, a long outage pushed out the earlier lines that
  said _why_ it started. The first failure is logged in full, repeats are
  counted, and recovery says how many there were.
- **Failures say what actually went wrong** — connection refused, authentication
  failed, a missing table — instead of the SQL alone.

**Also**

- **GLM 5.3 Flash** joins the model catalogue: a larger context than GLM 5.3,
  roughly nineteen times cheaper, and it can read images.

## v0.8.7 — Aug 27, 2026

Your agents work in the folder you gave them, you can see what they actually
built, and a coding CLI can now _be_ an agent — Codex as well as Claude Code.

**An agent writes where you told it to**

- **The folder you attach is the folder it uses.** Four runs in a row had
  delivered into the shared hand-off area while a real project folder sat
  attached and unused. The cause was not disobedience: the system prompt
  announced one workspace while the tools saw two.
- **The shared workspace is named for what it is** — the hand-off area between
  agents, not the place your deliverables go.

**Nodal stops guessing which folders are projects**

- **It shows the folders your agents wrote in, and gives you two gestures: rename
  and hide.** Seven different definitions of "real code" were tried and dropped,
  each breaking on a real case.
- **Hiding reaches the agents too.** A hidden project leaves every agent's
  runtime block, not just the screen. The folder on disk is never touched.
- **The name you choose travels.** Rename a project and your agents hear it under
  that name.

**An agent can be a coding CLI — Codex included**

- **Codex is selectable next to Claude Code** on an agent's Overview tab. The
  whole turn is served by that CLI: Nodal keeps the perimeter — folders, budget,
  approvals, channels — and relays its answer verbatim.
- **Write mode works on Windows.** It silently did nothing: the turn completed
  normally and the model answered "the environment forbids all writing" with no
  error anywhere.
- **Codex reports no cost, and the screen says so** instead of offering a dollar
  cap that cannot bound anything.

**Agents stop reporting work they did not do**

- An orchestrator announced "app delivered and reviewed by Reviewer C (2 passes)"
  four times in one day. No delegation, no write, no file. It was not lying — it
  was completing a pattern, because nothing in its history distinguished a real
  hand-off from an invented one. Delegation now leaves a structural trace on the
  turn that made it, so a turn **without** delegation carries no line at all.

**Hardening** — twenty-eight review passes, twenty-four findings

The most serious were not in this release's new code. They were asleep in code
that runs every day:

- **Tool output was written to the audit trail in clear text** — the content of
  every file a CLI session read, tokens included.
- **A tool restriction could be lifted by switching harness.** An agent with
  tools explicitly removed got them back when moved to a provider that cannot
  enforce that kind of ban. It now refuses the turn and says why.
- **The single-writer lock could be bypassed by spelling.** `C:/Common` and
  `c:\common` produced two separate locks.
- **The anti-loop guard undercounted parallel tool calls** — six simultaneous
  calls counted as one.
- **The workspace auto-run gate became one brake, not two locks.** Enabling Yolo
  per agent was already owner-only on both sides; the workspace switch keeps its
  real value, the emergency brake, and now applies in every auth mode rather than
  only on LAN.

## v0.8.6 — Aug 23, 2026

Your terminal can now hand work to your agents, and the dashboard follows you
to your phone — without either path being able to brick your install.

**Nodal as an MCP server, connectable in one line**

- **`claude mcp add nodal -- nodal-agents mcp serve`.** That is the whole
  setup. The new `mcp serve` CLI command resolves the database from your own
  install's config — no `DATABASE_URL` to know, no secret pasted into a client
  config, and it works on any npm install, not just a dev checkout. Settings
  shows the exact command with a Copy button.
- **One tool, `run_task`.** An external MCP client (your terminal, a coding
  agent) hands a request to your root agent — or a chosen agent by slug. The
  job runs through the normal loop: approvals, audit, budgets, and it can
  never touch the configuration tools. Off by default; a switch in Settings
  turns it on, and turning it off also cuts clients that are already connected.
- **Jobs start immediately.** `run_task` wakes the worker on creation like
  every other channel — measured before the fix, an MCP job waited ~2½ minutes
  for the periodic sweep.
- **The server exits when your client disconnects.** Closing stdin used to
  leave an orphan process holding Postgres connections; now both launchers
  close the pool and exit cleanly.

**LAN access that cannot dead-end**

- **The LAN toggle keeps your config bootable.** Switching to LAN used to be
  able to write a config the CLI refuses to start (network bind + no-password
  mode) — bricking the stack until a manual edit. The toggle now enables
  sign-in in the same write and says so.
- **An existing install gets a claim screen, not a dead login.** An install
  born without a password that switches to sign-in used to hit a wall: no
  password to sign in with, sign-up closed because the owner already exists.
  The login page now detects that state and offers **Create your account** —
  attached to the existing owner, so agents, settings and history stay exactly
  as they are. Validated end-to-end on a real migrated install, phone included.
- **Copy buttons work over plain-HTTP LAN.** The clipboard API is blocked on
  http; copy blocks now fall back so the button works exactly where LAN users
  need it.

**Hardening**

- The MCP job path was reviewed adversarially: the worker wake-up uses
  `127.0.0.1` (never `localhost`, which can silently resolve to IPv6 on
  Windows), rejected notifications are reported instead of swallowed, a
  deactivated agent is refused on every call, and a job insert that cannot
  report its id fails loud instead of answering success.
- ~30 vulnerable transitive dependencies pinned to patched versions across the
  workspace (hono, fast-uri, brace-expansion, js-yaml, nanoid, postcss, qs,
  body-parser, ip-address, vite, turbo) — and the pnpm overrides that were
  silently ignored since pnpm 10 moved to `pnpm-workspace.yaml`, where they
  actually apply.

## v0.8.5 — Aug 21, 2026

Fixes a package that broke itself weeks after it was published. **If you installed
0.8.0 or 0.8.1, upgrade — a fresh install of either is dead on arrival today.**

- **Every install since Aug 3 got a dashboard that crashed before it rendered.** The
  published package ships a _pre-compiled_ Next.js bundle, but declared 43 of its 46
  runtime dependencies as floating `^` ranges. The day `next@16.3.0` was published,
  npm started pairing a 16.3 runtime with a 16.2.6 build, and the server died on
  `TypeError: Cannot read properties of undefined (reading 'validationLevel')` before
  any application code ran. Installs of 0.8.1 made _before_ Aug 3 were unaffected.
- **A pre-compiled bundle now ships pinned to the exact versions it was built
  against.** `build-pack` rewrites all 46 runtime dependencies to their exact
  installed versions and fails the build if any range survives. A published package
  can no longer re-resolve its own runtime months later.
- **Next.js 16.3.** The workspace, the pack and the docs site all move to 16.3.0, and
  the pack was booted from an isolated install before release — every dashboard page
  served, not just `/api/health`.

**Coding under your subscription**

- **Agents can delegate development work to a coding CLI.** A new `code_task` tool
  hands a scoped task to Claude Code or Codex running under your own subscription,
  streams the work back, and records what was actually changed. Which CLI provider
  an agent uses is set per agent.
- **A Code tab.** Mission control for everything your agents write: files touched,
  the diff of the selected file, the activity trail per turn, and token accounting
  broken down per model.
- **Inference is now traceable.** Every LLM call and tool call is persisted and wired
  to the transcript, so a run can be read back after the fact instead of guessed at.

**Connectors and skills**

- **Cloudflare connector.** Deploy what your agents build straight to Workers, with
  the compatibility date pinned on every deploy.
- **ComfyUI in the MCP catalog**, via the official local `comfy-mcp` server.
- **The review loop closes.** Agents can request a review of their own work, and the
  verify-before-done skill picked up what the community version did better.

**Security — the audit is fully closed**

- **A stranger can no longer take over your bot.** A bot's username is public, and
  whoever messaged it first used to become its owner — so between pasting the token
  and sending your own first message, anyone who had found the bot could take your
  place, task your agent, and receive its approval cards. The first message now only
  _requests_ ownership; you approve it from the dashboard. Telegram, Discord, Slack
  and WhatsApp.
- **You see a skill update before it reaches your agents.** Updating a community
  skill used to show a category ("content changes") for text that goes straight into
  the system prompt of every agent holding it. You now get the actual diff, and the
  install refuses if upstream changed after you read it — consent applies to the text
  you saw, not to whatever the repo holds at click time.
- **Narrower Google access, and honest about the rest.** Google Calendar no longer
  asks for permission to delete your calendars. Drive, Sheets and Docs still need
  full access for their tools to work at all — so the product now says exactly how
  far that reaches, in plain language, before Google's consent screen.
- **Command injection through `cmd.exe` closed** — prompts are passed over stdin,
  never through a shell argument. Two independent reviews were run to closure.

**Reliability**

- **Office tools, one format at a time.** Spreadsheet, Document and Presentation
  editing are now separate skills. An agent that only touches workbooks stops
  carrying the Word and PowerPoint tool definitions — roughly 3,000 tokens off every
  turn, and 5,800 for a documents-only agent. The all-formats skill still exists.
- **A failed start now tells you what failed.** When a service doesn't come up, the
  CLI names which one it is still waiting for, how long it has waited, and prints the
  tail of that service's own log — where the actual cause has been sitting all along.
  `down` also verifies Postgres actually stopped before saying it did, and an
  orphaned Postgres is detected by its data directory rather than by an open port,
  which is the only way to see one that crashed during startup.
- **Ctrl+C is honoured from the moment Postgres starts**, not five minutes later —
  interrupting a slow first boot no longer leaves a database running behind.
- **Interrupting the dev server no longer strands a Next.js process on :3000.**
  Ctrl+C under a `.cmd` launcher makes Windows destroy the whole process group at
  once, the CLI's own cleanup included, mid-run — so cleanup cannot live there. The
  process tree is now recorded while the services are healthy, and the next start
  sweeps whatever survived, matching each process by creation time so a recycled PID
  is never mistaken for one of ours. It also reaches the deepest Turbopack worker,
  which holds no port and was therefore invisible to any port scan.
- **`up` refuses to kill a process it did not start.** A port it wants may be held
  by your own dev server; it now says so and stops, instead of freeing the port by
  destroying someone else's work.
- **`down` stopped crying wolf about Postgres.** `pg_ctl stop` returns when the
  signal is delivered, not when the postmaster is gone, so a stuck-database warning
  was firing on a database that was merely still on its way out.
- **Upgrades are tested against the real published package.** A new smoke test
  installs `nodal-agents@0.8.1` from npm, configures it, then installs this build
  over the top and checks it boots, serves a real page, keeps `pg-data`, and leaves
  the master key byte-identical — a changed key would make every stored credential
  permanently unreadable, silently. Fresh installs were already covered; the upgrade
  path, which is the one most people take, was not.
- **Windows is now in CI**, alongside the Linux suite, the Playwright smoke and
  approvals specs, and the packaging smoke. Every finding from the 0.8.1 audit is
  closed.

## v0.8.1 — Jul 31, 2026

Fixes a broken 0.8.0 package: on a fresh machine the dashboard could not render at
all. **If you installed 0.8.0, upgrade.**

- **Every dashboard page returned HTTP 500 on a fresh install.** The published
  0.8.0 tarball was missing 7 of the 40 server chunks its own pages require — the
  Next.js standalone output dropped them while copying the build, and nothing in
  the release pipeline compared what the build asks for against what ships. The
  home, agents, jobs, memories, settings, logs, MCP, automations, approvals,
  connectors, skills and onboarding pages were all affected. `/api/health` kept
  answering 200 throughout, so the CLI reported the runner as healthy.
- **The pack now ships the real build, and proves it.** `build-pack` copies the
  build's own `.next/server` over the standalone copy, then fails loudly if any
  page still requires a chunk that isn't there. `verify-install` runs the same
  check against an installed copy, and both are covered by tests that now run in CI.

## v0.8.0 — The Office Release · Jul 22, 2026

Your agents step into the workplace: Outlook mail, real Office documents, a per-agent thinking dial — plus a deep reliability pass on tool servers, connectors, and delegated workers.

- **Microsoft 365, connected.** A native Microsoft OAuth connector plus an Outlook mail toolset, alongside the existing Google, Notion, and Airtable connectors.
- **Agents that author documents.** A local office-authoring toolset builds real `.docx`, `.pptx`, and `.xlsx` files — multi-section documents, slides, spreadsheets with charts and pivots — failing loudly instead of producing silent half-files.
- **Choose how hard your agent thinks.** A reasoning-effort setting per agent (Auto / Off / low to max), applied per link of the fallback chain; the dashboard only offers levels the model actually supports.
- **Community skills, kept in sync — on your terms.** Installed skills track upstream updates with a badge and a bell. Updates are a true three-way merge with a "Keep your version" option when you've edited a skill locally, and script authorization is revoked before any new file is written.
- **Rate limits handled gracefully.** LLM 429/529 responses retry with a capped `Retry-After` backoff and fast-failover to a configured fallback model.
- **Reliability.** A hung remote tool server can no longer freeze an agent (per-server network dispatcher). Connector creation is idempotent, so a stuttering agent can't register duplicates. Delegated workers no longer speak on your channels or overwrite shared templates. Routines referencing a tool the agent doesn't have warn at creation time. A timed-out Telegram send is reported as ambiguous instead of retried into a duplicate.
- **Leaner and faster.** Dead tables dropped, a missing index added, N+1 queries batched, fetch timeouts tightened; typography fully on the design-system token scale and a new Table primitive across the dashboard.

## v0.7.95 — The Living Design System Release · Jul 16, 2026

The design system became a loop: Figma and the code are now mechanically tied together and checked by machine — and the last stock-browser UI joined the system.

- **Figma ↔ code, closed loop.** Every shared component is mapped to the Figma library, a drift check fails when they diverge, and a lint guard keeps all text on the type ramp.
- **Design-system dropdowns.** Select menus render the DS panel — surface, shadow, hover and selected states, section headers for grouped options — on Chrome/Edge, with a clean native fallback elsewhere. Placeholders grey out like every other field.
- **Agents page, redesigned.** Orchestrator cards with their workers, drag a worker across cards to reassign it, type-to-confirm delete in a danger zone, channels in their own tab.
- **Pick where notifications land.** Schedules and webhooks gained "Notify via" — results go to the channel you chose, and an unconnected channel fails loudly instead of falling back silently.
- **Docs, audited.** Ten pages corrected against the real code and four end-to-end channel connection guides.
- **Fixes.** Per-conversation reply channel, `/wh/v1` webhooks, MCP tool-load errors no longer kill jobs, plus a sweep of visual conformance fixes.

## v0.7.9 — The Design System Release · Jul 13, 2026

The whole dashboard now speaks one visual language, enforced so it can't drift — plus a rebuilt Google Gemini provider.

- **One consistent interface.** Every button, field, badge, pill, menu, and modal across the app is now a shared component. A lint rule makes raw, off-system elements fail the build, so the consistency holds for good — verified page by page, in light and dark.
- **Editing always happens in a modal.** No more inline accordions that shove the page around; every list edit opens a clean, non-dismissable dialog with a single Save/Cancel footer.
- **One grammar for row actions.** Icon-only square buttons with tooltips, one verb per icon, Delete always last, no hidden kebab menus.
- **End-to-end channel setup guides.** Connecting Discord, Slack, WhatsApp, or Telegram now walks you all the way to the first message — token setup, the ownership DM, the invite, and a "verify it works" step — in a properly formatted modal.
- **Google Gemini, rebuilt.** The native and OpenRouter Gemini paths were reworked (thought-signature round-trip on tool calls, native thinking config, 3.x catalog) so tool-calling agents run correctly on Gemini.
- **Polish.** The Settings page is now the same width as every other page, and Learned Skills uses the same per-agent assign/unassign toggle list as the Skills page — so you can finally unassign a learned skill.

## v0.6.2 — The Recall Release · Jun 28, 2026

Your agents remember — within a conversation, and across everything they've ever done.

- **Conversations that hold the thread.** Session memory measures a pause from when the reply was _delivered_, not when the job started — so a slow task no longer makes a quick follow-up look like an hour of silence. The idle reset widened (30 min → 4 h), the history budget grew, the reply's tail is kept, and a job that failed but spoke to you stays in the thread. Measured amnesia on a real 122-message conversation: 39% → 13%.
- **Two-tier memory.** Injected memory is ranked by relevance to the current task; every job's transcript is full-text searchable on demand via the new `search_history` tool (durable recall, zero standing context cost); and a background memory curator distills oversized facts, merges duplicates, and prunes the stale — never touching what you entered by hand.
- **3D & creative connectors.** Blender, Unity, Unreal Engine, KeyShot, and Photoshop (cross-platform) join the MCP marketplace under a new Creative category, each with a real brand icon.
- A longer MCP tool timeout (renders don't time out at 60 s) and a CI flake fix.

## v0.6.1 — The Vision Release · Jun 27, 2026

Send a picture on Telegram and your agents can actually look at it.

- **Inbound images.** A photo sent on Telegram now starts a job — it was silently dropped before. The image is saved to your shared workspace (`telegram/<chat>/<job>.<ext>`), reachable by the agent's file tools, and handed to the model — so "describe this image" works.
- **Vision routing, by real capability.** Each model's image support is read from the providers themselves (OpenRouter + models.dev) and surfaced in the orchestrator's team view. A text-only orchestrator routes the picture to a vision-capable teammate — the image travels with the delegation — or tells you plainly if none can see it. No guessing.

## v0.6.0 — The Clarity Release · Jun 25, 2026

Approvals that explain themselves, chat hand-offs that stay faithful, and session memory that knows when a conversation is over.

- **Approvals in plain language.** Every gated action (shell command, skill script, bundle write) leads with the agent's own one-line explanation of _what_ it's doing and _why_ — plus a ⚠️ impact line when it deletes, installs, or spends — instead of a wall of raw shell.
