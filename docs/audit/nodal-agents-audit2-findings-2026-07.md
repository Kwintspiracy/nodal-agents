## 0. Modèle de menace (établi par lecture, pas supposé) — recalibre tout

**Il n'existe AUCUN flux d'invitation de membre.** Les seuls INSERT dans `entity_members` sont : création de workspace (créateur = `owner`), signup local-auth, bootstrap local-trust. ⇒ **chaque entité a exactement 1 membre = son owner.** Conséquence : les scénarios « membre non-owner escalade dans l'entité d'autrui » sont **inexploitables** (owner-vs-membre intra-entité est vide de sens). Le seul axe multi-tenant réel = **user A (sa propre entité) vs user B (sa propre entité)** en mode **local-auth multi-user**. Le défaut d'installation est **local-trust mono-user** (aucune auth, un seul humain).

**Ce que ça implique pour la sévérité :** tous les findings « config globale / cross-tenant » (N-1 auth-settings, N-2 install-notes, setRoot, squat de slug) ne mordent QUE sur un déploiement local-auth ≥ 2 comptes. Ils sont réels mais **conditionnés**. Les findings vraiment déploiement-indépendants sont les 4 ÉLEVÉ ci-dessous.
