- **R1 — bloquant — `apps/cli/src/lib/orphans.ts:166`.** Le premier `-D` gagne dans le correctif, alors que PostgreSQL conserve le dernier. Reproduction exécutée : `postgres.exe -D C:/ours -D C:/foreign`, avec `dataDir=C:/ours`, produit `owned: [101]`. Le serveur utilise pourtant `C:/foreign`. Sans autre orphelin ni conflit préalable, la troisième sonde l’ajoute et `up.ts:377` le tue. L’ordre inverse refuse notre propre serveur. [Source PostgreSQL](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/postmaster/postmaster.c#L618).

- **R2 — bloquant — `apps/cli/src/lib/orphans.ts:197`.** Même correctement extrait, `-D` ne prouve pas le dossier de données effectif. Reproduction exécutée : `postgres.exe -D C:/ours -c data_directory=C:/foreign` produit `owned: [101]`. PostgreSQL utilise le dossier étranger ; le chemin vers `SIGKILL` reste celui de R1. Une surcharge dans `postgresql.conf` a le même effet. [Documentation PostgreSQL](https://www.postgresql.org/docs/18/runtime-config-file-locations.html).

- **R3 — important — `apps/cli/src/commands/up.ts:363`, `apps/cli/src/lib/postgres.ts:258`.** L’arrêt gracieux supposé avant la boucle ne fait rien. Dans le paquet installé `embedded-postgres@18.3.0-beta.17`, `dist/index.js:239` retourne immédiatement si `this.process` manque ; le handle nouvellement construit n’en possède pas. Avec un fichier PID présent et un orphelin vivant, `stopOrphanPostgres()` retourne donc `true` sans signaler aucun processus, puis la boucle passe au `SIGKILL`. Ce défaut préexistant invalide la garantie sur laquelle repose le correctif C7.

- **R4 — mineur — `apps/cli/src/lib/postgres.ts:127`.** Les dates produites ne sont pas des millisecondes Unix exactes hors fuseau UTC. Reproduction PowerShell exécutée : l’époque littérale devient `1970-01-01T08:00:00+08:00`, de type `Local`. Pour `2026-09-14T16:56:16.154Z`, l’expression donne `1789376176154`, contre `1789404976154` réellement. Le décalage commun de huit heures ne change toutefois pas l’ordre des processus d’une même sonde.

1. **constat** — R1 et R2. Pour les formes demandées, vérification sur la fonction actuelle : espaces non cités → refus ; apostrophe dans le nom → reconnu ; apostrophes utilisées comme délimiteurs → refus ; UNC identique → reconnu ; forme 8.3 comparée au chemin long → refus ; `--pgdata="…"` → reconnu ; `^` devant un espace → refus. `\"` interne n’est pas décodé correctement, mais `"` n’est pas un caractère valide de nom de dossier Windows. Le paquet installé utilise directement `spawn(postgres, ['-D', databaseDir, '-p', …])`, sans shell : ses arguments ordinaires, y compris les espaces correctement cités par Node, sont couverts.

2. **tient** — Le paquet transmet `databaseDir` sans résoudre ses alias ; il pourrait transmettre `..` si l’appelant le fournissait. Ici, `PG_DATA_DIR` provient de `join(homedir(), '.nodalai', 'pg-data')`, qui normalise les segments. Deux alias différents restent effectivement différents pour le classificateur, mais les jonctions de `node_modules` ne modifient pas cet argument. Aucun refus systématique propre aux worktrees n’est établi.

3. **tient** — PostgreSQL écrit `DataDir` en ligne 2, après conversion en chemin absolu ; ce traitement n’impose pas une résolution des jonctions pour un chemin déjà absolu. Le lancement et la vérification utilisent ici le même `PG_DATA_DIR`. Un changement d’alias entre deux lancements serait refusé, mais la jonction du paquet ne suffit pas à le provoquer. Vérification des sources, sans lancement de cluster sous jonction. [Sources PostgreSQL](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/utils/init/miscinit.c), [traitement des chemins](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/port/path.c).

4. **tient** — Une table lisible doit primer sur le fichier périmé. Un postmaster sans socket reste détectable par sa commande WMI. S’il est mort, son PID ne justifie plus un arrêt ; s’il manque réellement dans WMI tout en vivant, il échappe effectivement au nettoyage. Faire gagner le fichier dans ce cas rouvrirait C3.

5. **NON TRANCHÉ** — L’absence de date désactive bien le garde, explicitement documenté à `orphans.ts:35` et `:127`. Une fausse filiation redevient alors possible. Je n’ai pas établi les conditions réelles produisant une ligne PostgreSQL sans `CreationDate` : la sandbox refuse entièrement WMI, ce qui ne démontre pas une propriété individuellement absente.

6. **NON TRANCHÉ** — Des dates égales passent ; l’arrondi en millisecondes perd de la précision. Pour une vraie filiation, cette acceptation est correcte. Pour adopter un étranger, il faudrait aussi que le parent meure et que son PID soit réattribué dans cette même fenêtre temporelle. Ce scénario réel n’a pas été établi ; l’égalité seule ne prouve pas une mauvaise attribution.

7. **constat** — R3. Aucun arrêt du cluster ne précède effectivement les destructions. Tuer un worker avant le postmaster peut déclencher la récupération et la création de nouveaux processus ; la liste parcourue reste celle de la sonde initiale. Le postmaster présent dans cette liste sera néanmoins tenté si aucune vérification précédente ne lève. [Gestion des processus PostgreSQL](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/postmaster/postmaster.c).

8. **tient** — Le premier survivant interrompt bien les tentatives suivantes. C’est un arrêt sur échec explicite : ni annonce de nettoyage réussi ni nouveau démarrage ne sont atteints. Cela ne reproduit pas C7, qui laissait poursuivre après un nettoyage incomplet.

9. **tient** — Hors Windows, l’arbitrage retombe sur le fichier, avec désormais le contrôle supplémentaire de sa ligne 2. Sur Windows, chaque retour explicite `read: false` écrit `ORPHAN_PROBE_UNREADABLE`. L’import d’`execa`, placé avant le `try`, peut échouer sans ce code, mais il rejette alors l’appel au lieu de retourner `read: false`. Le repli sur un fichier périmé conserve le risque de PID recyclé lorsque la table est indisponible.

10. **constat** — R4. La soustraction produit bien un `TimeSpan`, mais l’époque littérale est locale. Le décalage est commun aux lignes ; il ne démontre donc pas une inversion autour d’un changement d’heure. La valeur fournie correspond exactement au calcul fautif reproduit ci-dessus, sans permettre de certifier l’heure réelle du processus historique. Le test « VERBATIM » valide le parseur ; sa commande `powershell` ne valide pas une ligne issue du filtre `Name='postgres.exe'`.

11. **tient** — Une stratégie `Restricted` autorise les commandes individuelles ; l’absence de `-ExecutionPolicy Bypass` n’est donc pas une erreur pour cette commande intégrée. L’exécution réelle tentée ici échoue sur un refus d’accès WMI et retourne le statut `1`, correctement couvert par le correctif C6. [Documentation Microsoft](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies).
